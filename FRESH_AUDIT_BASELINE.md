# Fresh SK Coder Audit Baseline

This baseline records only behavior and defects verified from the repository, the new master specification, and live browser checks on 2026-08-15. It is the gate for the new rebuild pass: changes will target these gaps while keeping the approved VS Code-style layout and existing AI and GitHub provider choices.

| Area | Verified finding | Impact | Rebuild decision |
|---|---|---|---|
| TypeScript and linting | Root TypeScript disables `noImplicitAny` and `strictNullChecks`; lint reports 23 errors and 11 warnings. | The project does not meet the requested strict-quality gate. | Tighten type safety in first-party IDE code and make lint pass without hiding errors. |
| TypeScript build | `npx tsc -b --noEmit` currently fails on missing Vite environment declarations, an unchecked terminal tab type, and an incorrectly inferred Vite config value. | The project can build with Vite but does not pass a direct TypeScript project check. | Add correct Vite client typings, resolve the terminal type boundary, type the Vite config, and include this check in release validation. |
| Offline terminal | Live test of `mkdir notes` returned `mkdir: command not found. Type help.` | The terminal claims a local workspace shell but lacks required Phase 1 commands. | Implement a stateful browser virtual filesystem for `ls`, `cd`, `pwd`, `mkdir`, `rm`, `cat`, `cp`, `mv`, `echo`, `grep`, and `find`. |
| Node fallback | The dependency list has no Nodebox package. The local fallback runs generic browser JavaScript, not Node.js. | The UI can misrepresent browser JavaScript as Node execution. | Remove misleading Node claims, route to the backend when available, and preserve a clearly labelled browser JavaScript fallback when Nodebox is not installed. |
| Execution scope | The current terminal exposes C/C++, Java, Kali, and Git Bash alongside Wandbox and Piston services. | This conflicts with the new Phase 1 specification, which limits Phase 1 to Python, Node.js, and Bash. | Hide or defer non-Phase-1 runtimes from the Phase 1 terminal workflow rather than advertising unsupported capabilities. |
| Codespaces | CloudShell launches `window.open` for a Codespaces page. | This violates the specification requirement that Codespaces does not open new tabs. | Remove the new-tab behavior and present an in-app connection state with an explicit capability limitation until a genuine embedded terminal endpoint is available. |
| Git panel | No Git panel, Git operation source, or browser Git dependency is present. | Required push, pull, stage, and commit actions are absent rather than merely untested. | Add a minimal authenticated GitHub repository panel only after validating the existing Device Flow contract. |
| Browser project run | `runWorkspaceProject` returns a message that package scripts require the backend. | Project execution is a visible stub. | Route project-run attempts to the configured backend and give an actionable offline fallback message. |
| File and folder runners | Folder actions named `Open via Node.js`, `Open via Python`, and `Open via Bash` only switch terminal tabs and issue `ls`. | Context actions imply execution but do not execute a file or project. | Rename non-executing actions or connect them to actual file/project routing after virtual filesystem support is complete. |
| Storage | IndexedDB stores only one imported workspace snapshot and has no restore API or recovery UI. | Workspace persistence and fallback claims are incomplete. | Implement reliable persisted workspace restore and use IndexedDB as the canonical browser workspace store. |
| Import | ZIP import reads every entry as text and lacks binary safeguards, drag-and-drop, progress, and duplicate-path policy. | Imported projects can corrupt or silently lose non-text assets. | Add safe file classification, duplicate normalization, drag-and-drop, and explicit skipped-file feedback. |
| Import merge policy | The top-bar import flow appends imported trees to the existing workspace without a replace, merge, or conflict-resolution choice. | Re-importing projects can create duplicate or ambiguous file paths. | Add a clear import mode and deterministic conflict policy while preserving the existing Open control. |
| Docs and legal pages | Guide, Privacy, and Terms pages are one-line placeholder content. | The documented Phase 1 deliverables are not met. | Replace with substantive, product-specific pages that disclose local storage and 72-hour backend retention. |
| Repository onboarding | `README.md` still says `Welcome to your Lovable project` and contains only a documentation TODO. | Setup, architecture, test, and deployment handoff information is missing and the inherited scaffold identity remains visible. | Replace it with SK Coder-specific onboarding and remove unused scaffold branding. |
| AI configuration | Generic OpenAI-compatible validation and chat code exists. `usePuter` is stored but has no visible fallback flow. | Existing approved AI logic is not fully testable or surfaced. | Preserve provider logic; add validation tests, clear errors, and a non-promoted optional fallback capability check only. |
| Watermarks and tags | No production import or rendered reference to a watermarking or platform tagging tool was found. `lovable-tagger` is an unused development dependency. | No visible watermark exists, but the unused dependency is unnecessary. | Remove the unused package and keep source and rendered UI free of branding markers not chosen by the owner. |
| Placeholder image | About renders `/saqlain.jpg` and hides the image on error, leaving an empty avatar treatment when the asset is absent. | The UI retains a non-functional placeholder visual. | Remove the placeholder image dependency and use the existing product mark instead. |
| Oracle terminal | The backend terminal client is a line-based command socket with no terminal emulation, cwd, prompt, resize, or interactive PTY state. | The UI can be mistaken for an interactive terminal although it is command-at-a-time execution. | Keep it clearly scoped as secure command execution or implement genuine terminal capabilities before calling it an interactive terminal. |
| UI evidence | The initial IDE shell, Explorer, editor, Terminal, and mobile navigation render without browser console errors. | The approved layout is viable and should not be replaced. | Preserve the visual structure and correct behavior inside existing panels. |

## Baseline validation

The existing six frontend unit tests and production build pass, but this is insufficient evidence of application completeness. The current lint command fails with 23 errors and 11 warnings. The browser test demonstrated a concrete terminal failure for a required command. This baseline therefore treats successful compilation as necessary but not sufficient for release readiness.

During Phase 2 validation, the new import listener initially exposed a missing React effect import in `TopBar`. The browser reported the exception, the import was corrected immediately, and the refreshed IDE rendered with zero browser errors. This validates the audit rule that every changed user flow must receive a live browser check rather than relying only on the production build.
